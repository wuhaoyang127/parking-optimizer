# 阶段 A 提示词：研究、审查与最终路线决策

你正在一个国家级大学生创新项目仓库中工作。当前阶段只做研究与路线决策，不实现完整程序。

## 必须先做

1. 阅读仓库根目录 `AGENTS.md`、`PROJECT_STATUS.md`、`.agent/PLANS.md`、`README.md`。
2. 阅读 `references/original/` 下两份 Word：
   - 大创项目申请书；
   - Dijkstra-SA 算法说明文档。
3. 阅读 `docs/候选算法路线.md`，把其中路线视为“待证伪的候选假设”，不是不可推翻的结论。
4. 创建并维护 `docs/plans/stage-a-research.md`，严格遵守 ExecPlan。
5. 先给我展示计划、检索问题、交付文件和验收方式。计划得到确认后再继续。

## 项目事实

- 目标停车场同时支持普通独立车位和纵深式车位，纵深式是重要扩展；
- 纵深式场景重点考虑车位有效利用率、移位次数和移位距离；
- 当前真实数据只有平面图、车位坐标、道路连接、入口和出口数量；
- 初步实验必须使用明确标注的仿真数据；
- 规模约 100 个物理停车位置；
- 普通 Windows 笔记本运行；
- 最终成果要可仿真验证，并能发展为现实停车场管理系统的决策模块；
- 可以彻底否定申请书和旧算法路线，但必须解释为什么仍符合立项目标；
- 不做真实自动驾驶转向控制、感知或 Hybrid A* 轨迹规划。

## 核心任务

### 1. 审查原始方案

逐项审查申请书中的 ARIMA-SA、ARIMA-ACO、ARIMA-RF，以及旧文档中的 Dijkstra-SA。

对每个模块说明：

- 它真正解决什么问题；
- 输入、输出和数据要求；
- 在当前项目中是否必要；
- 是否存在时间尺度错位、算法角色混淆、目标不清、未来信息假设、不可验证或算力问题；
- 结论属于：保留、修改、仅作对照、暂缓、否定；
- 给出证据，不得凭直觉。

### 2. 大规模但高质量的文献调研

围绕以下主题检索论文和作者代码：

- dynamic parking allocation；
- rolling horizon / model predictive parking assignment；
- autonomous valet parking slot assignment；
- stacked/tandem parking relocation；
- shared parking supply-demand matching；
- discrete-event parking simulation；
- exact integer/constraint programming for assignment and scheduling；
- online parking assignment；
- parking utilization and relocation metrics。

至少形成 15—25 条高相关来源的文献矩阵。优先近十年高质量期刊、会议、学位论文、作者公开代码和官方工具文档，同时保留少量奠基文献。

每条来源记录：

- 题名、作者、年份、出处；
- DOI或稳定链接；
- 是否获得全文；
- 问题类型；
- 信息假设；
- 数学模型；
- 求解方法；
- 数据规模；
- 对比基线；
- 结果指标；
- 可复现代码；
- 对本项目可直接借鉴的内容；
- 不适用之处。

不得伪造。只有摘要时明确说明。

### 3. 比较候选路线

至少比较以下候选：

1. Dijkstra + 模拟退火；
2. 遗传算法或其他元启发式；
3. CP-SAT/MILP 离线优化；
4. 滚动时域 CP-SAT/MILP；
5. 基于规则的在线算法；
6. 强化学习；
7. 监督学习预测 + 优化；
8. 你通过文献发现的其他合理路线。

建立决策矩阵，维度至少包括：

- 与项目目标一致性；
- 纵深阻挡表达能力；
- 利用率表达；
- 动态到达能力；
- 数据需求；
- 解释性；
- 可验证性；
- 普通笔记本可行性；
- 100 车位可扩展性；
- 实现难度；
- 论文与展示价值；
- 现实接入可能性；
- 失败风险。

不要因为候选路线写在 `docs/候选算法路线.md` 就给高分。

### 4. 作出最终路线决定

选择一条主路线和必要的对照路线。最终结论必须明确：

- 核心研究问题；
- 系统边界；
- 普通车位和纵深车位如何统一；
- 离线全信息基准、在线即时策略，以及最终批准的动态决策方式各自用途；
- 若不采用滚动时域或其他动态方法，说明理由；
- 是否需要预测；
- 核心决策方法及其实现工具；
- 超时和数据不足时的降级策略；
- 为什么不选其他路线；
- 与申请书目标的连续性；
- 现实部署需要补采哪些数据。

### 5. 数据与实验可行性

提出分三级验证方案：

1. 极小人工例：可手算或穷举；
2. 仿真数据：多场景、多种子；
3. 后续真实数据：字段、采集频率、隐私和校准方法。

重点说明没有真实到达/离场数据时，哪些结论可以成立，哪些不能成立。

## 禁止事项

- 不写完整仿真器、优化器、Streamlit；
- 不先定结论再找证据；
- 不把搜索摘要写成论文全文结论；
- 不编造真实数据、实验结果或“提升百分比”；
- 不宣称全球最优算法；
- 不把 ARIMA、随机森林、强化学习当作必须保留的创新点；
- 不修改 `references/original/`；
- 不自动开始阶段 B。
