# 阶段 C 总控提示词

阶段 C 的目标是把已批准的阶段 B 规格实现为可运行、可测试、可复现的核心系统。

现在只做：

1. 阅读 `AGENTS.md`、`PROJECT_STATUS.md`、`.agent/PLANS.md` 和阶段 A/B 的批准文档；
2. 核对 `prompts/C/` 是否已经根据阶段 B 结果更新；
3. 若模板仍含与批准路线不一致的算法或工具，先提出修改，不实施业务代码；
4. 创建 `docs/plans/stage-c-implementation.md`；
5. 把阶段 C 分为 C1—C7，每个子阶段明确文件、测试、演示和停止条件；
6. 设计 Python 3.11 Windows 环境、最小依赖和安装方案；
7. 展示计划并等待用户批准 C1。

建议的通用子阶段：

- C1：环境、包结构、领域模型和输入校验；
- C2：路网、布局、需求与仿真输入；
- C3：阶段 B 批准的仿真/事件引擎和基线；
- C4：阶段 B 批准的精确或高质量基准；
- C5：阶段 B 批准的动态核心算法和降级策略；
- C6：冻结协议下的批量实验、统计和报告；
- C7：全面审查、性能和复现。

这里的子阶段名称是通用职责，不是对 SimPy、CP-SAT、滚动时域或其他具体技术的预先决定。
