# 项目状态更新与新对话交接提示词

## A. 新对话开始时

```text
请先不要修改任何文件。依次读取：

1. AGENTS.md
2. PROJECT_STATUS.md
3. .agent/PLANS.md
4. 若 current_exec_plan 不为 null，读取其指向的文件；为 null 时跳过
5. 若 latest_handoff 不为 null，读取其指向的文件；为 null 时跳过
6. 与本任务直接相关的权威文档和代码

用不超过十行说明：

- 项目当前阶段及验收状态；
- 已完成并验证的内容；
- 已批准或冻结的决定；
- 尚未冻结的关键问题；
- current_stage_blockers；
- downstream_blockers 及其阻止的阶段；
- 当前唯一下一步；
- 本次任务包含与不包含的范围；
- 准备读取或修改的文件；
- 是否存在需要我确认的关键歧义。

不得猜测 null 指针指向的文件。在我确认前，不要进行大规模或不可逆修改。
```

## B. 任务结束时更新状态

```text
请在任务已实际完成并运行必要验证后，检查是否需要更新 PROJECT_STATUS.md。

更新规则：

1. 只记录已实际完成、已验证或已由用户批准的变化；
2. 不把计划、推测、未运行测试或未验收成果写成已完成；
3. 不隐藏测试失败、降级、当前阶段阻断项、下游阻断项或主算法表现不佳的结果；
4. 阶段切换、核心路线、冻结定义和完成状态必须经用户确认；
5. 详细过程保留在 ExecPlan，不复制到 PROJECT_STATUS.md；
6. 最近重要变更最多保留 10 条；
7. 确保“当前唯一下一步”只有一个清晰入口；
8. current_stage_blockers 只记录直接阻止当前阶段的问题，并使用单行 JSON 字符串数组；
9. downstream_blockers 使用单行 JSON 对象数组，每项必须有 target_stage 和 issue；
10. 更新后运行 `python scripts/validate_starter_package.py`，检查真实 Git 分支和状态指针；
11. 更新后检查状态与 ExecPlan、代码、测试和权威文档一致；
11. 先展示 PROJECT_STATUS.md 的 Diff 摘要，再等待我接受。
```

## C. 阶段结束时

阶段结束除更新 `PROJECT_STATUS.md` 外，还应在 `docs/handoffs/` 中建立唯一阶段交接摘要，包含：

- 阶段目标和主要结论；
- 已批准或冻结的决定；
- 关键文件与运行入口；
- 实际运行的测试和结果；
- 失败案例与已知限制；
- 下一阶段进入条件；
- 仍需用户决定的事项。

`PROJECT_STATUS.md` 只保留项目级摘要并链接到交接文件，不复制完整内容。

## D. 多线程规则

只有项目主线程或用户指定的协调线程可以直接提交 `PROJECT_STATUS.md`。其他线程只能提供：

- 建议修改的字段；
- 修改理由；
- 证据文件和测试结果；
- 建议的下一步。

由主线程核验并合并，避免多个对话相互覆盖进度。
