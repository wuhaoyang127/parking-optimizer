# 部署与运维说明（研发端 · 企业试点版）

> 适用对象：负责部署研发端 Streamlit 应用、维护 Supabase 后端的人员。
> 配套文件：`Dockerfile`、`docker-compose.yml`、`.env.example`、`deploy/nginx.conf.example`、`.streamlit/secrets.toml.example`、`migrations/0*.sql`。

---

## 1. 一次性初始化：Supabase 数据库迁移

在 Supabase 控制台 → SQL Editor，按顺序执行（**顺序不可乱**）：

| 顺序 | 文件 | 内容 |
|---|---|---|
| 1 | `migrations/01_setup.sql` | 用户表 + 认证 RPC |
| 2 | `migrations/02_preferences.sql` | 用户偏好 |
| 3 | `migrations/03_feedback.sql` | 意见反馈 |
| 4 | `migrations/04_feedback_display_time.sql` | 反馈显示时间 |
| 5 | `migrations/05_security_hardening.sql` | **bcrypt + 审计日志 + search_path 加固** |
| 6 | `migrations/06_sim_runs.sql` | **仿真运行记录** |

**重要**：`01_setup.sql` 底部有初始管理员账号（`wuhaoyang127`），占位密码是 `CHANGE_ME_ADMIN_PASSWORD`。首次部署前必须改掉；已运行的系统不会因重复执行而覆盖现有密码（`ON CONFLICT DO NOTHING`）。

**重要（密钥轮换）**：代码历史里曾包含旧的 Supabase publishable key。企业上线前请到 Supabase 控制台 → Settings → API Keys **轮换 publishable key**，并把新 key 配置到部署环境（见下节）。

## 2. 密钥配置（三选一，推荐顺序）

| 方式 | 适用 | 做法 |
|---|---|---|
| 环境变量（推荐） | Docker / 云平台 | 设置 `SUPABASE_URL`、`SUPABASE_ANON_KEY` |
| `.streamlit/secrets.toml` | Streamlit Cloud / 本地 | 复制 `.streamlit/secrets.toml.example` 填写后放入 `.streamlit/`（已被 .gitignore 忽略） |
| 代码默认值 | 仅本地开发 | 不推荐生产使用 |

`src/auth.py` 的读取优先级：`st.secrets` → 环境变量 → 默认值。

## 3. 部署方式

### 3.1 Docker 单机（推荐试点）

```bash
cp .env.example .env          # 填入真实密钥
docker compose up -d --build  # 构建并后台启动
docker compose logs -f app    # 看日志
```

健康检查：`http://<主机>:8501/_stcore/health` 返回 `ok`。

### 3.2 Streamlit Community Cloud（最省事，公网演示）

1. 仓库推送到 GitHub；
2. Community Cloud 新建 app，指向 `app.py`；
3. 在 App Settings → Secrets 配置：
   ```toml
   [supabase]
   SUPABASE_URL = "..."
   SUPABASE_ANON_KEY = "..."
   ```
4. 注意：免费版 Cloud 应用闲置会休眠，冷启动较慢；正式试点建议用 Docker 自托管。

### 3.3 HTTPS（自托管）

- 方案 A：前面加 nginx，参考 `deploy/nginx.conf.example`（含 WebSocket 升级、健康检查、上传大小限制）；
- 方案 B：云厂商负载均衡/网关直接终止 HTTPS，转发到 8501；
- 证书：Let's Encrypt（certbot）或云厂商免费证书。
- Streamlit 的「另存为…」按钮依赖安全上下文（HTTPS 或 localhost），HTTP 下会自动降级为普通下载。

## 4. 数据备份

| 层级 | 做法 |
|---|---|
| 云端自动备份 | Supabase Pro 提供每日自动备份；免费版请在 Dashboard 手动导出 |
| 手动 pg_dump | `pg_dump "postgresql://postgres:<DB_PASSWORD>@db.<ref>.supabase.co:5432/postgres" --schema=public > backup_$(date +%F).sql`（连接串在 Supabase → Settings → Database） |
| 关键表定期导出 | 系统设置页已提供「用户导入/导出」；运行记录/反馈可走页面 CSV 导出 |
| 备份内容 | `users`、`user_preferences`、`feedback`、`sim_runs`、`audit_log` 五张表 |

建议：试点期间每周手动 `pg_dump` 一次，文件存到企业指定位置。

## 5. 监控与日志

| 项 | 做法 |
|---|---|
| 应用健康 | 轮询 `/_stcore/health`；Dockerfile 内置 HEALTHCHECK |
| 应用日志 | `docker compose logs -f app`；生产可接 Loki/云日志 |
| 后端可用性 | 应用内「系统状态」页主动探测 Supabase 在线状态与 key 有效性 |
| 操作审计 | `audit_log` 表记录登录/退出/角色变更/反馈处理/仿真运行等，建议每月导出留存 |
| 错误告警 | Streamlit 异常会写入容器日志；可对接 Sentry 或在云平台配置日志告警 |

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 登录一直提示「用户名或密码错误」 | 可能未执行 05 迁移且密码是旧哈希；确认迁移全部执行；管理员用初始密码登录一次触发透明升级 |
| 刷新后登录态丢失 | Cookie 未生效（浏览器禁 Cookie / HTTP 非安全上下文）；重新登录即可，不影响使用 |
| 运行记录页为空 | 先运行一次仿真才会写入；确认已执行 06 迁移 |
| Supabase 请求报 401/403 | publishable key 已轮换但应用未更新；更新密钥后重启应用 |
| 云部署后自定义布局保存失败 | 检查系统状态页的 Supabase 健康探测；本地桌面运行时自带本地备份自愈 |
