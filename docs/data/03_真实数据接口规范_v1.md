# 真实数据接口规范 v1（企业对接预留）

> 状态：预留规范，供企业合作试点对接使用。
> 原则：**只读接入**——系统只读取道闸/车位数据用于验证与演示，不反向控制任何真实设备。
> 实现：`src/parking_opt/io/realtime_io.py`（CSV 解析 + 转换）；后续 HTTP/WebSocket 接口沿用同一字段规范。

---

## 1. 总览

| 数据 | 来源 | 用途 | 对接形态 |
|---|---|---|---|
| 道闸流水 | 车牌识别 + 道闸系统 | 车辆到达/离场时序 → 需求序列 | CSV 导出（已实现）/ HTTP 接口（预留） |
| 车位状态快照 | 地磁 / 高位相机 / 车位锁 | 实时占用状态 → 推荐输入 | CSV 导出（已实现）/ WebSocket 推送（预留） |
| 布局数据 | CAD / 平面图 / 车位坐标 | 路网与车位模型 | JSON 导入（已实现，见 `docs/布局导入格式说明.md`） |

字段规范版本：`realtime_schema_v1`。

## 2. 道闸流水（Gate Records）

### 2.1 CSV 格式（已实现解析）

| 字段 | 必填 | 别名（兼容） | 类型 | 说明 |
|---|---|---|---|---|
| 车牌 | 是 | plate / plate_no / 车牌号 | string | 建议导入前脱敏；系统默认按 SHA-256 脱敏 |
| 入场时间 | 是 | entry_time / 入场时间 | ISO 字符串或 epoch 秒 | `2026-08-30 08:00:00` 或 `1753843200` |
| 出场时间 | 是 | exit_time / 出场时间 | 同上 | 必须晚于入场时间 |
| 入口编号 | 否 | entry_id / 入口 | string | 与布局 JSON 中 `type="entry"` 节点对应 |
| 出口编号 | 否 | exit_id / 出口 | string | 与布局 JSON 中 `type="exit"` 节点对应 |

示例：

```csv
plate,entry_time,exit_time,entry_id,exit_id
京A12345,2026-08-30 08:00:00,2026-08-30 09:30:00,entry_1,exit_1
京B67890,2026-08-30 08:05:00,2026-08-30 08:35:00,entry_1,exit_1
```

### 2.2 转换为需求序列

- 仿真 0 时刻 = 最早入场时间；
- `arrival_time` = 入场时间 − 基准时间；
- `parking_duration` = 出场时间 − 入场时间；
- `estimated_duration` = 真实时长 × (1 ± error_ratio)，默认 `error_ratio=0`；
- 输出为现有需求序列 JSON（schema v1，`source="real_gate"`），可直接复用全部仿真与评估流程。

### 2.3 HTTP 接口（预留）

```
GET /api/v1/gate-records?from=2026-08-30T00:00:00Z&to=2026-08-31T00:00:00Z
```

返回 JSON 数组，元素字段同 2.1 表（`plate` 建议服务端已脱敏）。对接实现时复用 `realtime_io.gate_records_to_vehicles()`。

## 3. 车位状态快照（Spot Status）

### 3.1 CSV 格式（已实现解析）

| 字段 | 必填 | 别名（兼容） | 类型 | 说明 |
|---|---|---|---|---|
| 车位编号 | 是 | spot_id / 车位号 | string | 与布局 JSON 中车位节点 id 对应 |
| 占用状态 | 是 | occupied / 状态 | 1/0、true/false、占用/空闲 | 大小写不敏感 |

示例：

```csv
spot_id,occupied
S001,1
S002,0
```

### 3.2 实时推送（预留）

```
WS /api/v1/spot-status   →  {"spot_id": "S001", "occupied": true, "ts": "..."}
```

## 4. 隐私与合规要求（企业对接必读）

1. **车牌属于个人信息**：默认脱敏（SHA-256 前 10 位），原始车牌不落库、不出现在界面与导出文件中；
2. 对接前与企业签署**数据使用授权协议**，明确数据仅用于算法验证与试点评估；
3. 试点期间系统**只读**，不向道闸/车位锁下发任何控制指令；
4. 数据保存位置、留存期限、销毁方式需在协议中约定。
