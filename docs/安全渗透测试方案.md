# 安全渗透测试方案

> 状态：Phase 3 安全加固与测试准备（2026-11-21）
> 范围：车主端（FastAPI + React，Render）与研究端（Streamlit，Streamlit Cloud），共享 Supabase。

## 1. 范围与攻击面

| 目标 | 入口 | 风险点 |
|---|---|---|
| 车主端 | `/api/v2/auth/login`、`/api/v2/recommendations`、`/api/v2/journeys/*`、`/api/research/*` | 登录暴力破解、越权、输入注入 |
| 研究端 | 登录/注册、算法 zip 上传、布局/需求导入、反馈 | XSS（unsafe_allow_html）、文件上传、越权 |
| Supabase | RPC（login_user 等）、PostgREST 直连 | 密钥泄露、RLS 绕过、SQL 注入 |

## 2. 已完成加固（本次 Phase 3）

- **登录速率限制（车主端）**：同一用户名 5 次失败 / 5 分钟窗口 → HTTP 429（`app_routes_auth.py`）。
- **安全头（车主端）**：`nosniff`、`Referrer-Policy`、`X-Frame-Options: SAMEORIGIN`、`HSTS`、`Permissions-Policy`、`CSP`（`serve.py`）。
- **研究集成鉴权**：Bearer token 用 `secrets.compare_digest` 常数时间比较，防时序侧信道（`research_api.py`）。
- **输入校验**：FastAPI pydantic 严格模型（`extra=forbid`、`Identifier` pattern、范围校验），失败关闭。
- **错误脱敏**：统一异常处理器返回通用 500，不回传堆栈。
- **密码哈希**：bcrypt（migration 01，老 sha256 登录时透明升级）。
- **密钥管理**：`st.secrets` / 环境变量注入，不提交 `.env`/密钥；service key 仅服务端使用。

## 3. 待办加固（建议后续）

1. **研究端登录服务端锁定**：`login_user` RPC 无服务端失败计数/锁定，需新增 migration（DB 层计数 + 临时锁定）。
2. **XSS**：研究端 `st.markdown(unsafe_allow_html=True)` 渲染用户名/反馈等用户内容，需对用户输入做 HTML 转义或改用 `unsafe_allow_html=False`。
3. **文件上传**：算法 zip / 需求 CSV 上传需限制大小、类型，并防 zip bomb（解压前校验压缩比）。
4. **CSP 收紧**：若 React 无内联脚本，保持 `script-src 'self'`；若后续引入内联需显式审查。
5. **会话轮换**：登录成功/改密后轮换 session token，缩短过期时间。
6. **CORS 白名单**：当前同源部署无需 CORS；若拆独立前端，显式配置允许源。

## 4. OWASP Top 10 映射与测试用例

| # | 漏洞 | 本项目对应点 | 测试方法 | 预期 |
|---|---|---|---|---|
| A01 | 越权 | `/api/research/*`、`/api/admin/*` | 无 token / 错误 token 调用 | 401，不泄露数据 |
| A02 | 加密失败 | 密码哈希、HTTPS | 检查 hash 算法、证书 | bcrypt；强制 HTTPS |
| A03 | 注入 | Supabase RPC、PostgREST | 用户名/参数带 SQL 元字符 | 被参数化，无注入 |
| A04 | 不安全设计 | 速率限制、错误信息 | 连续失败登录 | 429 拦截 |
| A05 | 配置错误 | 密钥、CORS、调试 | 检查响应头、是否泄露 stack | 无泄露 |
| A07 | 身份认证失败 | 登录/会话 | 弱口令、会话伪造 | 锁定 + token 校验 |
| A03/A07 | 暴力破解 | `/api/v2/auth/login` | 脚本连续尝试同用户 | 5 次后 429 |
| A09 | 日志监控缺失 | 审计日志 | 检查 audit_log 覆盖 | 登录/关键操作有记录 |

## 5. 测试工具

- **OWASP ZAP**：自动化主动/被动扫描（spider + active scan），覆盖 A01–A07。
- **Burp Suite Community**：手工重放、篡改请求、越权测试。
- **sqlmap**：对可疑注入点跑注入检测（本项目为 RPC/参数化，预期无发现）。
- **浏览器 DevTools**：验证 CSP/HSTS 头、XSS payload、控制台报错。

## 6. 执行步骤

1. 部署最新代码后，用 ZAP 对 `https://parking-driver.onrender.com` 与研究端 URL 各跑一轮 baseline scan。
2. 手工复现：登录暴力破解（确认 429）、无 token 调 `/api/research/v1/capabilities`（确认 401）、改密后旧 token 失效。
3. XSS：研究端反馈/用户名插入 `<script>`、`<img onerror>`，确认是否执行。
4. 记录每个测试的实际结果与修复措施，形成测试报告。

## 7. 验收标准

- 登录暴力破解被 429 拦截（5 次 / 5 分钟）。
- 未授权访问管理/研究接口返回 401/403，无数据泄露。
- 响应无堆栈、无密钥、无调试信息。
- 车主端 CSP/HSTS/Permissions-Policy 头存在且生效。
- XSS payload 不执行（或已列入待办并给出修复计划）。
- 所有失败案例保留记录，不宣称"零风险"。
