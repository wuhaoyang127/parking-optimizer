# 04 候选算法比较

## 评估框架

### 评估维度定义

| # | 维度 | 含义 | 评分（1-5，越高越好） |
|---|---|---|---|
| D1 | 项目目标一致性 | 算法核心机制是否直接服务于"利用率+移位+等待"目标 | 5=完全对齐 |
| D2 | 纵深阻挡表达 | 能否形式化建模纵深阻挡与移位操作 | 5=完整表达 |
| D3 | 利用率表达 | 能否定义和优化车位时空利用率 | 5=直接优化 |
| D4 | 动态到达能力 | 能否处理车辆实时到达（非全量预知） | 5=天然在线 |
| D5 | 数据需求 | 所需输入数据的可获得性 | 5=仅需仿真数据即可 |
| D6 | 解释性 | 本科生能否理解、答辩、伪代码讲清楚 | 5=完全可解释 |
| D7 | 可验证性 | 能否建立正确性验证和公平对比 | 5=有精确基准 |
| D8 | 笔记本可行性 | 在普通笔记本(16GB RAM)上运行 | 5=轻松运行 |
| D9 | 100车位可扩展性 | 100停车位规模下的计算效率 | 5=秒级求解 |
| D10 | 实现难度 | 组员在Python 3.11下的实现难度 | 5=简单 |
| D11 | 论文与展示价值 | 学术新颖性和成果展示效果 | 5=有创新点 |
| D12 | 现实接入可能性 | 后续接入真实停车场管理系统的难度 | 5=接口简单 |
| D13 | 失败风险 | 无法完成、无法验证、效果不如基线的概率 | 5=风险极低 |

### 算法不可直接比较时的处理
当两条路线在不同信息条件下运行时（如离线全信息 vs 在线有限信息），它们不直接竞争同一角色，而是分属不同层级。比较时应先明确各路线在系统中的角色定位。

## 8条候选路线详细评估

### 1. Dijkstra + 模拟退火 (Dijkstra-SA)

**角色定位**：离线批量优化或在线周期性重优化

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 4 | 综合代价函数直接包含路径、等待、阻塞、未满足四个目标，与立项目标对齐。权重设定缺乏依据(-1) |
| D2 阻挡表达 | 2 | 当前R只统计阻挡次数，不建模真实移位操作（移去哪、连锁效应、时序）。这是最需要增强的维度 |
| D3 利用率表达 | 3 | 通过"未满足需求得分"间接反映，缺少直接的时空利用率公式 |
| D4 动态到达 | 2 | 当前实现是批量离线（所有需求已知后一次优化），需要改造为在线触发 |
| D5 数据需求 | 5 | 仅需路网+仿真需求，均可自生成 |
| D6 解释性 | 5 | 文档已提供中文可读公式、变量表、伪代码，本科生友好 |
| D7 可验证性 | 3 | 有随机和最近路径基线，但无法知道离最优有多远（无 optimal gap） |
| D8 笔记本可行 | 4 | 100车位×数百车辆可在笔记本运行；3000迭代约需数分钟 |
| D9 100车位 | 3 | SA收敛速度随问题规模增加；每方案评估需遍历所有车辆和车位 |
| D10 实现难度 | 4 | 已有可运行代码；组员修改参数/改进即可 |
| D11 展示价值 | 3 | SA是成熟技术，创新性有限；但可视化（路网图+收敛曲线+对比图）效果好 |
| D12 现实接入 | 4 | 输入为路网+车辆到达，与真实停车场数据接口匹配 |
| D13 失败风险 | 2 | 可能不如简单规则（离场顺序贪心），阻塞改进后 SA 的有效性待证明 |
| **加权总分** | **3.2** | (各维等权粗略平均) |

---

### 2. 遗传算法或其他元启发式 (GA/PSO/ACO)

**角色定位**：替代SA的元启发式求解器

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 4 | 同SA，目标函数可复用 |
| D2 阻挡表达 | 2 | 取决于目标函数设计，同SA |
| D3 利用率表达 | 3 | 同SA |
| D4 动态到达 | 2 | 同SA，离线批量 |
| D5 数据需求 | 5 | 同SA |
| D6 解释性 | 3 | GA的交叉/变异/选择机制对本科生而言比SA的"温度→接受概率"更抽象 |
| D7 可验证性 | 3 | 同SA，无 optimal gap |
| D8 笔记本可行 | 3 | GA通常需要更大的种群和更多迭代 |
| D9 100车位 | 3 | 种群×迭代×每个体评估 |
| D10 实现难度 | 3 | 编码方案设计（如何把分配编码为染色体）需仔细设计；交叉/变异可能破坏可行性 |
| D11 展示价值 | 3 | GA也是成熟技术 |
| D12 现实接入 | 4 | 同SA |
| D13 失败风险 | 2 | 编码设计不当会导致大量不可行解 |
| **加权总分** | **2.8** | SA 更简单且已有代码，GA没有明显优势 |

**结论**：GA/PSO/ACO 不提供相对于 SA 的根本性优势。若 SA 效果不佳，更应先考虑精确方法而非换一个元启发式。

---

### 3. CP-SAT/MILP 离线全信息优化

**角色定位**：小规模精确基准（offline oracle）

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 5 | 目标函数和约束可直接用数学形式精确编码 |
| D2 阻挡表达 | 5 | 布尔变量编码阻挡关系、移位操作链，CP-SAT 天然适合 |
| D3 利用率表达 | 5 | 直接将利用率公式纳入目标或约束 |
| D4 动态到达 | 1 | **完全离线**：所有车辆需求一次性已知。不适用于动态决策 |
| D5 数据需求 | 5 | 同其他方法，仿真数据即可 |
| D6 解释性 | 3 | 约束编程概念（子句学习、传播）比SA抽象；但数学模型本身可解释 |
| D7 可验证性 | 5 | **提供最优性 gap**，这是元启发式无法提供的最大优势 |
| D8 笔记本可行 | 3 | 100车位×大量车辆的MILP可能很慢；需通过滚动时域或缩小规模使用 |
| D9 100车位 | 2 | 全量离线MILP在100车位×180车辆规模下可能超时 |
| D10 实现难度 | 3 | OR-Tools CP-SAT API友好，但建模约束需要运筹学基础 |
| D11 展示价值 | 5 | **精确方法的"最优性证明"是答辩中的亮点**；与启发式对比展示 gap |
| D12 现实接入 | 2 | 全信息假设不现实 |
| D13 失败风险 | 2 | 大规模可能超时无解，需时间限制和降级 |
| **加权总分** | **3.5** | **关键价值：提供离线基准。不应作主算法但必须保留** |

---

### 4. 滚动时域 CP-SAT/MILP (Rolling Horizon)

**角色定位**：动态在线主算法

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 5 | 在滚动窗口内精确优化全部目标 |
| D2 阻挡表达 | 5 | 同CP-SAT，窗口内完整建模阻挡与移位 |
| D3 利用率表达 | 5 | 同CP-SAT |
| D4 动态到达 | 4 | 每次触发（新到达/定时）在窗口内优化，只看窗口内信息。接近真实动态运营 |
| D5 数据需求 | 4 | 需要短期预测（窗口内可能到达的车辆），可仿真提供也可用简单估计 |
| D6 解释性 | 3 | 滚动框架直觉可讲，但CP-SAT内部仍是黑盒 |
| D7 可验证性 | 4 | 窗口内最优可证；全局可通过仿真比较 |
| D8 笔记本可行 | 4 | 窗口内问题规模可控（如最近10辆+未来10分钟），求解压力远小于全量MILP |
| D9 100车位 | 4 | 窗口内规模可控 |
| D10 实现难度 | 2 | 需要 CP-SAT建模 + 滚动框架 + 状态管理，实现复杂度最高 |
| D11 展示价值 | 5 | **滚动时域精确优化是论文级的创新点**；对比离线基准和在线基线有丰富故事 |
| D12 现实接入 | 4 | 滚动框架与真实停车场"D秒决策"的模式匹配 |
| D13 失败风险 | 3 | 窗口内CP-SAT可能偶尔超时→需要降级规则；但降级后仍有可行解 |
| **加权总分** | **3.9** | **综合最优候选之一，但实现难度高** |

### 5. 基于规则的在线算法

**角色定位**：对照基线和降级策略

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 3 | 规则可明确优化某个子目标（如最少移位），但多目标协调靠人工设计 |
| D2 阻挡表达 | 4 | 规则可显式编码"有阻挡风险时优先选独立车位"等策略 |
| D3 利用率表达 | 3 | 间接 |
| D4 动态到达 | 5 | 天然在线，规则即时执行 |
| D5 数据需求 | 5 | 仅需当前状态 |
| D6 解释性 | 5 | **可解释性最佳**：每条规则都有明确语义 |
| D7 可验证性 | 3 | 无法知道离最优多远；但规则之间可对比 |
| D8 笔记本可行 | 5 | 瞬时执行 |
| D9 100车位 | 5 | O(n)或O(n log n) |
| D10 实现难度 | 5 | 最简单 |
| D11 展示价值 | 2 | 规则方法创新性低，但"精心设计的规则打败元启发式"也是好故事 |
| D12 现实接入 | 5 | 规则可直接部署 |
| D13 失败风险 | 4 | 规则一定返回结果；可能效果不好，但不会失败 |
| **加权总分** | **3.7** | **必须保留为基线+降级，可能成为主算法一部分** |

### 6. 强化学习 (RL)

**角色定位**：学习型动态策略

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 4 | 奖励函数可设计为综合目标 |
| D2 阻挡表达 | 3 | 状态空间需要编码阻挡关系，维度可能爆炸 |
| D3 利用率表达 | 3 | 可通过奖励间接表达 |
| D4 动态到达 | 5 | 天然在线决策 |
| D5 数据需求 | 1 | **需要大量训练 episode**（仿真或真实）；无仿真器无法训练 |
| D6 解释性 | 1 | **黑盒**：神经网络策略难以解释，答辩困难 |
| D7 可验证性 | 2 | 难以证明策略的最优性或安全性 |
| D8 笔记本可行 | 2 | 训练可能需要数小时至数天 |
| D9 100车位 | 2 | 状态动作空间大，需要大量训练 |
| D10 实现难度 | 1 | **最高**：需要RL框架、环境建模、调参、稳定性处理 |
| D11 展示价值 | 4 | "RL用于停车"有一定新颖性，但不是核心创新 |
| D12 现实接入 | 2 | RL策略的鲁棒性在真实环境中未经检验 |
| D13 失败风险 | 1 | **高风险**：训练不收敛、过拟合仿真、不如规则基线 |

### 7. 监督学习预测 + 优化

**角色定位**：预测停车时长/离场时间→优化器使用预测

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 3 | 预测本身不优化，而是为优化器提供输入 |
| D2 阻挡表达 | 3 | 取决于优化器 |
| D3 利用率表达 | 3 | 取决于优化器 |
| D4 动态到达 | 4 | 预测可在线更新 |
| D5 数据需求 | 1 | **需要大量标注数据**（历史停车记录）训练预测模型 |
| D6 解释性 | 2 | 预测模型（RF/XGBoost）解释性中等；完整流水线复杂 |
| D7 可验证性 | 3 | 预测精度可单独验证；优化效果依赖预测精度 |
| D8 笔记本可行 | 3 | 小规模训练可行 |

| D11 展示价值 | 4 | "预测+优化"是标准范式，不是创新但完整 |
| D12 现实接入 | 3 | 需要真实数据训练 |
| D13 失败风险 | 2 | 预测不准→优化效果差，两阶段风险叠加 |
| **加权总分** | **2.5** | **无真实数据前不推荐，可在论文中讨论作为未来扩展方向** |

### 8. 离场顺序贪心 + 缓冲位策略（文献启发的简单智能规则）

**角色定位**：强基线或轻量主算法

思路：
- 优先分配独立车位或纵深组的 depth=1 车位
- 若不得不分配 depth>1，选预计离场时间最早的内侧车辆后方
- 预留1-2个缓冲位用于临时移位
- 当被阻挡车辆离场时，阻挡车移入缓冲位→被阻挡车驶出→阻挡车归位（或留在缓冲位）

| 维度 | 评分 | 说明 |
|---|---|---|
| D1 目标一致性 | 4 | 移位距离最小化是显式目标 |
| D2 阻挡表达 | 4 | 缓冲位机制显式建模了移位操作流程 |
| D3 利用率表达 | 3 | 间接 |
| D4 动态到达 | 5 | 在线即时决策 |
| D5 数据需求 | 5 | 仅需当前状态+（可选的）预计离场 |
| D6 解释性 | 5 | "先独立后纵深+缓冲位"直觉可讲 |
| D7 可验证性 | 4 | 可与离线最优和随机基线对比 |
| D8 笔记本可行 | 5 | 瞬时 |
| D9 100车位 | 5 | O(n) |
| D10 实现难度 | 5 | 简单规则+状态管理 |
| D11 展示价值 | 3 | 规则方法创新性有限，但"简单有效"也是好故事 |
| D12 现实接入 | 5 | 可直接部署 |
| D13 失败风险 | 4 | 规则一定返回结果 |
| **加权总分** | **3.8** | **作为对照基线或轻量主方法都有价值** |

## 关键发现

1. **没有一条路线在所有维度上最优**。需要分层组合：精确基线 + 动态主方法 + 简单降级 + 对照基线。

2. **滚动时域 CP-SAT (路线4)** 在"目标一致性+阻挡表达+可验证性+展示价值"上得分最高，适合作为**主研究路线**。代价是实现难度高。

3. **贪心+缓冲位 (路线8)** 在"动态性+解释性+可行性+风险"上全面领先，适合作为**对照基线和降级策略**。甚至可能效果接近或超过 SA。

4. **CP-SAT 离线 (路线3)** 在小规模上提供最优性基准，不可替代。所有动态方法的效果上限由它定义。

5. **Dijkstra-SA (路线1)** 虽然评分中庸，但已有可运行代码，适合作为**工程起点和对照基线**。

6. **RL (路线6) 和预测+优化 (路线7)** 当前不推荐——数据需求和失败风险过高，在大创项目的约束下不可行。
