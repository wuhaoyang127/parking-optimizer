# 候选算法路线：待阶段 A 证伪或确认

## 1. 文件定位

本文不是最终路线结论，只记录当前最值得优先研究的候选假设。阶段 A 必须把它与 Dijkstra-SA、遗传/退火类元启发式、整数规划、在线规则、预测加优化、强化学习及文献中其他方法进行公平比较。

若证据不支持本文路线，应明确否定或修改。

## 2. 候选方案

> **路网成本预处理 + 可校准的事件仿真 + 小规模高质量基准 + 动态车位分配优化 + 确定性降级策略**

一种可能实现是：

1. 使用图算法预计算入口、出口、车位和缓冲位之间的路径成本；
2. 使用离散事件仿真重放车辆到达、等待、入位、离场、阻挡与移位；
3. 使用精确或有界求解器处理极小/小规模全信息实例，提供基准；
4. 使用当前信息和有限预测进行动态分配；
5. 求解超时或数据不足时使用可解释规则安全降级；
6. 用统一日志和指标与随机、最近车位、FCFS、离场顺序贪心及旧方案比较。

NetworkX、SimPy 和 OR-Tools CP-SAT 是可能工具，但阶段 A/B 通过前不强制。

## 3. 为什么值得优先研究

- 当前约 100 个车位，普通笔记本有机会在有限窗口内求解；
- 纵深阻挡、移位、容量和时序约束需要明确可行性表达；
- 小规模高质量基准可以判断启发式结果离最优有多远；
- 动态框架比提前知道全天车辆更接近现实；
- 仿真器可以在真实时序数据不足时验证逻辑，但必须明确结论边界；
- 规则降级使系统在超时或缺数据时仍能给出可解释动作。

## 4. 需要重点证伪的问题

阶段 A 必须回答：

- 约束优化是否能在目标规模和时间预算下运行；
- 纵深移位是否能被可实现地表达，而不是只给风险分数；
- 动态优化是否真的优于简单离场顺序贪心；
- 是否有更轻量、解释性更高的替代路线；
- 当前缺少真实时序数据时，预测模块是否必要；
- 旧 Dijkstra-SA 是否值得保留为正式基线；
- 候选路线是否过度复杂，是否需要进一步收缩。

## 5. 当前不优先的方向

在没有充分数据和基线前，不优先把下列方法作为核心：

- ARIMA/SARIMA：目前缺少真实连续历史序列；
- 随机森林：它是预测模型，不会自动求解组合分配；
- 强化学习：训练、稳定性、解释和公平比较成本较高；
- Hybrid A*、DQN控制：超出管理层车位分配的项目边界。

这些方向可以在阶段 A 重新评估，但不能只因名称先进而加入。

## 6. 路线通过阶段 A 的最低条件

只有同时满足以下条件，候选路线才可进入阶段 B：

- 有可靠文献和原始来源支持；
- 与普通/纵深混合场景和项目目标一致；
- 输入数据需求可以通过仿真或后续采集满足；
- 100 车位规模在普通笔记本上有明确的复杂度控制；
- 能建立公平基线和小规模验证基准；
- 能明确现实系统接口和结论边界；
- 团队可以逐步理解、实现和答辩。

通过后，阶段 B 再确定具体求解器、仿真工具和动态算法。
