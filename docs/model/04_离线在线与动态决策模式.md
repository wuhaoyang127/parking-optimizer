# 04 离线在线与动态决策模式

---

## 1. 三种决策模式概述

| 模式 | 信息条件 | 触发 | 用途 |
|---|---|---|---|
| **离线 Oracle (CP-SAT)** | 全部车辆到达时间+真实停车时长 | 一次求解 | 性能上界 |
| **在线贪心 (Greedy)** | 当前状态 + 历史均值估计 | 每辆车到达时 | **主方法** |
| **降级 FCFS** | 当前状态 | 主方法不可用时 | 安全网 |

---

## 2. 离线 Oracle：CP-SAT 全信息基准

### 2.1 适用规模
- 10-20 车位，20-40 辆车（小规模）
- 全信息：所有车辆 `arrival_time` + `parking_duration` 已知

### 2.2 CP-SAT 建模要点

**决策变量**：
- `x[v][s]`：bool，车辆 v 分配到车位 s
- `occ[s][t]`：bool，车位 s 在时刻 t 被占用
- `block[v1][v2]`：bool，v1 阻挡 v2
- `shift[v]`：bool，v 需要移位

**约束**（CP-SAT 表达）：
- 一车一位：`sum(x[v][s] for s) = 1`
- depth 可用性：`x[v][s]=1 ⇒ 时刻 arrival[v] 时 s 及其外侧均空闲`
- 时间不重叠：若 x[v1][s]=1 且 x[v2][s]=1，则 [arrival[v1], dep[v1]) ∩ [arrival[v2], dep[v2]) = ∅

**求解时限**：300 秒；超时则取当前最佳可行解

### 2.3 产出
- 已知最优（或带 gap）的满足率、利用率、移位次数
- 所有在线策略的上界参照

---

## 3. 在线贪心：主方法

### 3.1 决策流程

```
算法: ONLINE_GREEDY(vehicle v, time t, parking_lot state)

输入: v.arrival_time, v.estimated_duration(=历史均值), 当前状态
输出: (assigned_spot, rejection_reason) 或 (None, "rejected")

Step 1: 收集可分配车位
    candidates = []
    for spot in parking_lot.spots:
        if spot.is_available():
            candidates.append(spot)

Step 2: 若 candidates 为空
    if 有等待队列且等待时间 < 300s:
        加入等待队列, 返回 (None, "waiting")
    else:
        return (None, "rejected")

Step 3: 按优先级排序 candidates
    priority(spots):
        1. STANDALONE 独立车位 (depth=1, stack_group 唯一)
        2. TANDEM depth=1 (靠通道的纵深车位)
        3. TANDEM depth>1 (外侧已被占的内侧车位)

Step 4: 同优先级内选择
    # Priority 1-2: 选路径距离最近的
    # Priority 3: 选内侧车预计离场最早的(减少阻挡风险)
    estimated_dep_of_inner = v_inner.arrival_time + v_inner.estimated_duration
    pick the spot where min(estimated_dep_of_inner)

Step 5: 分配
    spot.is_occupied = True
    spot.occupied_by = v.id
    return (spot, None)
```

### 3.2 复杂度
- 收集候选：O(|\mathcal{S}|)
- 排序：O(|\mathcal{S}| log |\mathcal{S}|)
- 总计：O(|\mathcal{S}| log |\mathcal{S}|) ≈ 100·log(100) ≈ 460 操作，秒级完成

## 4. 降级 FCFS

### 4.1 触发条件
- 在线贪心计算时间 > 1 秒
- 在线贪心返回不可行解
- 路网数据不完整
- 仿真状态异常

### 4.2 FCFS 规则

```
算法: FALLBACK_FCFS(vehicle v, time t, parking_lot state)

Step 1: 收集所有空闲可分配车位 (同贪心)
Step 2:
    if candidates 非空:
        选择第一个可用的独立车位或 depth=1 车位 (不排序直接取)
        return (spot, "fcfs")
    else:
        return (None, "rejected")
```

### 4.3 降级记录
```json
{
    "event": "degradation",
    "time": "2026-08-04T10:30:00",
    "reason": "greedy_timeout",
    "original_method": "online_greedy",
    "fallback_method": "fcfs",
    "affected_vehicle": "V0042"
}
```

## 5. Dijkstra-SA 对照基线

### 5.1 改造要点
- 原实现为批量离线（所有需求已知），需改为周期性批量触发
- 每 N 辆车到达后（如 N=10）运行一次 SA 重优化
- SA 使用与贪心不同的信息：已知窗口内已到达车辆的信息

### 5.2 SA 参数
| 参数 | 默认值 |
|---|---|
| 初始温度 | 1000 |
| 降温速率 | 0.95 |
| 迭代次数 | 3000 |
| 邻域操作 | 随机重分配、两车交换 |

---

## 6. 对照基线列表

| 基线 | 规则 | 复杂度 |
|---|---|---|
| **FCFS** | 最先到达→最近可用独立或depth=1车位 | O(n) |
| **最近路径** | 最近可用车位（忽略阻挡） | O(n) |
| **随机** | 随机可用车位 | O(n) |
| **离场顺序贪心** | 最近车位，若需选depth>1则选内侧最早离场的 | O(n log n) |
| **Dijkstra-SA** | 周期性 SA 批量重优化 | O(n·iter) |
| **CP-SAT Oracle** | 全信息精确（仅小规模） | NP-hard |

## 7. 事件驱动仿真流程

```
SimPy 仿真主循环:

while 仿真时间 < 结束时间:
    next_event = min(所有待处理事件)
    跳到 next_event.time

    switch next_event.type:
        case VEHICLE_ARRIVAL:
            spot = ONLINE_GREEDY(vehicle, time, state)
            if spot:
                调度 SPOT_ENTRY 事件(vehicle → spot, 行驶 time)
            else if wait:
                调度 WAIT_START 事件
            else:
                记录 REJECTED

        case SPOT_ENTRY:
            vehicle 入位, spot.is_occupied = True
            调度 DEPARTURE 事件(vehicle, departure_time)

        case DEPARTURE:
            if 被阻挡:
                触发 SHIFT_START 事件
            else:
                vehicle 驶出, spot.is_occupied = False

        case SHIFT_START:
            buffer = SELECT_BUFFER(time)
            if buffer:
                阻挡车 驶入 buffer
                调度 SHIFT_END 事件
            else:
                记录 BUFFER_FAILED, 降级处理

        case SHIFT_END:
            被阻挡车 驶出离场
            阻挡车 从 buffer 归位(或前移)
            buffer 释放
```
