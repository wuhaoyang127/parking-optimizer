# 车主端接入契约（研发端 → 车主端 算法发布/校验/启用）

本文档约定：研发端「新算法接入 → 🚀 推送到车主端」如何把算法发布到车主端暂存区、
经车主端服务端校验后显式启用，以及失败回滚与执行回执的语义。

> 旧版契约（发布写 Supabase `algorithm_releases`，车主端读表进入实验）已被本契约取代；
> 旧表数据仅作为「📜 历史研究记录」在研发端页面只读展示，不再控制车主端。

---

## 1. 总流程

```text
研发端 Streamlit「新算法接入 → 🚀 推送到车主端」
   │ 服务端直连车主端 FastAPI（密钥不进浏览器）
   ▼
车主端 FastAPI
   │ POST /api/research/v1/releases        发布到暂存区（不生效）
   │ POST /api/research/v1/releases/{id}/validate   服务端兼容性校验
   │ POST /api/admin/v1/driver-algorithm-activations  CAS 原子启用/回滚
   ▼
车主创建新请求 → FastAPI 先做可行性判断/权威路由/原子锁位，
再调用已启用版本的研究算法对可行候选排序 → 返回推荐与执行回执
```

- 发布**只暂存**；校验通过后**另点启用**才影响新请求，存量行程保留原版本与推荐证据。
- 回滚即把激活指针切回 `online-rule-v2`（默认在线规则），秒级生效。
- 算法只消费 FastAPI 校验过的可行候选与可见投影，不接触 SessionStore 或未来真值。

## 2. 服务地址与鉴权

| 项 | 值 |
|---|---|
| 车主端 FastAPI | 本机默认 `http://127.0.0.1:8000`；远程必须 HTTPS |
| 车主端网页 | 本机默认 `http://127.0.0.1:4173`（研发端侧边栏「🚗 打开车主端」） |
| 推送控制台 | 本机默认 `http://127.0.0.1:8501`（未配置 API 时研发端页面跳转目标） |

两个服务端密钥至少 32 字符，随请求头 `Authorization: Bearer <token>` 发送：

- `PARKING_PUBLISH_TOKEN`：读 capabilities、发布/读 releases；
- `PARKING_ADMIN_TOKEN`：校验、启用/回滚、执行回执、观测导入、会话/历史导出。

普通车主的 `X-Session-ID` 不授予任何管理权限；密钥只在研发端服务端环境/Secrets 配置。

## 3. 研发端配置（Streamlit secrets 或环境变量）

```toml
[driver_bridge]
PARKING_DRIVER_API_URL = "http://127.0.0.1:8000"      # 远程必须 https://
PARKING_DRIVER_WEB_URL = "http://127.0.0.1:4173"
PARKING_PUBLISH_TOKEN = "与车主端服务完全一致的发布密钥(≥32字符)"
PARKING_ADMIN_TOKEN = "与车主端服务完全一致的独立管理密钥(≥32字符)"
PARKING_DRIVER_CONSOLE_URL = "http://127.0.0.1:8501"   # 可选，未配置 API 时的跳转地址
```

配置齐 `PARKING_DRIVER_API_URL` + `PARKING_PUBLISH_TOKEN` 后，「新算法接入」页自动显示
发布/校验/启用完整面板；未配置时显示跳转按钮，可在装有车主端的电脑上打开独立控制台。

## 4. 端点清单

- `GET /api/research/v1/capabilities`：10 种在线适配策略 + mosa 研究状态、参数范围、源码 hash
- `POST /api/research/v1/releases` / `GET .../releases`：发布到暂存区 / 发布历史
- `POST /api/research/v1/releases/{id}/validate`：服务端兼容性校验（逐项通过/失败）
- `POST /api/admin/v1/driver-algorithm-activations` / `GET .../active`：CAS 启用/回滚 / 当前版本
- `GET /api/admin/v1/execution-receipts`：最近 100 条执行/校验/切换回执
- `POST /api/admin/v1/visible-observations`：导入/读取按会话隔离的可见观测
- `GET /api/admin/v1/driver-sessions`、`driver-input-context`、`completed-history.csv`：会话、数据缺口与历史导出

## 5. 发布载荷

```json
{
  "release_id": "research-<uuid hex>",
  "algorithm_id": "rho_rolling",
  "source_hash": "<capabilities 返回的 64 位 hex，必须与车主端安装的研发源码一致>",
  "params": {},
  "note": "",
  "seed": 0,
  "model": null
}
```

- `source_hash` 变化（研发源码改动）时旧版本不能启用，需重新发布并校验；
- canonical JSON 采用 UTF-8、排序键、无多余空白，保留数组顺序并拒绝 NaN/Infinity；
- `ml_duration_tree` 必须绑定已训练 JSON 模型（不接受 Python/pickle），且模型训练时间
  不得晚于请求时点；`mosa` 是离线全信息研究策略，不允许发布为在线推荐。

## 6. 在线输入与信息边界

- 输入只含 as_of 当时可见的布局/状态/成本、当前请求、用户预计停留（可留空）及标注来源的预测；
- duration/risk/RHO/ML 等策略缺必要输入时明确失败或降级，不自动合成时长代替未知；
- 观测按 `session_id` + `parking_lot_id` 隔离，核对 layout_hash、时点、300 秒新鲜度与
  synthetic/observed 来源；
- 每个子进程执行预算 2 秒；失败保留回执并回退，回执记录 requested/executed 算法、
  输入 hash、seed、降级原因与发布 hash。

## 7. 保留 / 回滚

| 决策 | 操作 |
|---|---|
| 启用新版本 | 校验通过后 `POST /api/admin/v1/driver-algorithm-activations`（带 expected_active_hash 的 CAS） |
| 回滚 | 同端点发布 `release_id = null`；新请求恢复 online-rule-v2，存量行程保留原版本证据 |
| 审计 | `GET /api/admin/v1/execution-receipts` 查看实际执行算法与降级原因 |

## 8. 旧 Supabase 契约（历史存档）

旧版依赖 `algorithm_releases` / `experiments` / `experiment_assignments` / `experiment_events`
四张表与 RPC `publish_algorithm` 等，现已**不再控制车主端**；表与 RPC 保留用于历史展示，
「新算法接入」页第三页签「📜 历史研究记录」仍可只读查看。

## 9. 安全边界

- 跨站通道仅允许本机 HTTP 或远程 HTTPS，API 地址禁止携带账号、口令、查询参数或片段；
- 发布/管理端点全部服务端鉴权，密钥不进入浏览器与前端构建产物；
- 研发端不直接 import 车主端代码，车主端通过独立 Python 子进程执行冻结的研发源码，
  输出上限与超时严格受限。
