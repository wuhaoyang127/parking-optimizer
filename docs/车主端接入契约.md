# 车主端接入契约（研发端 → 车主端 算法实验）

本文档约定：研发端「推送到车主端」发布的算法快照，车主端（React + FastAPI）如何消费并进入实验。

---

## 1. 总流程

```
研发端 Streamlit「新算法接入 → 🚀 推送到车主端」
   │ 写 Supabase public.algorithm_releases（仅管理员）
   ▼
车主端 FastAPI
   │ 读 algorithm_releases 最新一条 → 得到 (algo_name, params)
   │ 读 experiments 当前实验 → 得到流量比例与对照组算法
   │ 按 user_id 哈希分桶 → control（默认算法）/ treatment（新算法）
   │ 调用 parking_opt 的 StrategyRegistry.create(name, **params).assign(...)
   │ 写 experiment_assignments（首次命中固定分组）+ experiment_events（每次调用指标）
   ▼
一个月后：研发端看 experiment_events 对比，保留 = 把新算法设为默认；退回 = 流量置 0
```

## 3. 读取发布快照（service_role）

```python
# 用 Supabase service_role key 直连（绕过 RLS）
releases = supabase.table("algorithm_releases") \
    .select("*").order("created_at", desc=True).limit(1).execute()
latest = releases.data[0]          # {"algo_name": "rho_rolling", "params": {...}, ...}
```

## 4. 在线调用契约（核心）

车主端需构造停车场状态对象，然后调用算法策略的 `assign`：

```python
from parking_opt.domain.spot import Vehicle, SpotType
from parking_opt.routing.path_engine import PathEngine
from parking_opt.simulation.parking_lot import ParkingLot
from parking_opt.strategies import StrategyRegistry

# 1) 路网（与研发端布局 JSON 同构：nodes/edges，见 docs/布局导入格式说明.md）
net = ...          # RoadNetwork 或从布局 JSON 构建
pe = PathEngine(net)

# 2) 停车场当前状态：车位占用情况
lot = ParkingLot(spots)   # spots: list[Spot]

# 3) 到达车辆（在线信息：只给当前状态与预估时长，不给真实停车时长）
vehicle = Vehicle(vehicle_id="P1A2B3C4D5", arrival_time=now,
                  estimated_duration=1800, entry_id="ENTRY", exit_id="EXIT")

# 4) 实例化算法（params 来自发布快照）
strategy = StrategyRegistry.create(latest["algo_name"], **latest["params"])

# 5) 调用：返回 (Spot 或 None, 状态)
spot, status = strategy.assign(vehicle, now, lot, pe)
# status ∈ {"assigned", "waiting", "rejected"}
```

信息边界（项目硬约束）：`assign` 只允许读当前车位状态、已发生的到达离开、已知预约、预估离场；**不得读真实停车时长**（`vehicle.parking_duration` 仅供仿真/评估）。

## 5. 实验分流（FastAPI 中间件示例）

```python
import hashlib

def get_bucket(user_id: str, exp_id: str) -> int:
    h = int(hashlib.md5(f"{exp_id}:{user_id}".encode()).hexdigest(), 16)
    return h % 100

def route_algo(user_id: str, exp: dict) -> str:
    """返回本次应使用的算法名（algo_default 或 algo_new）。"""
    if exp.get("status") != "running":
        return exp["algo_default"]
    bucket = get_bucket(user_id, exp["id"])
    group = "treatment" if bucket < exp["traffic_pct"] else "control"
    # 首次命中写 experiment_assignments 固定分组（主键 experiment_id+user_id，幂等 upsert）
    supabase.table("experiment_assignments").upsert({
        "experiment_id": exp["id"], "user_id": user_id,
        "bucket": bucket, "group_name": group,
    }, on_conflict="experiment_id,user_id").execute()
    return exp["algo_new"] if group == "treatment" else exp["algo_default"]
```

灰度节奏：`traffic_pct` 从 5 → 20 → 50 → 100 逐步放量，改表即生效，无需发版。

## 6. 指标事件上报

每次算法调用后写 `experiment_events`：

```python
supabase.table("experiment_events").insert({
    "experiment_id": exp["id"],
    "user_id": user_id,
    "algo_version": used_algo,        # algo_default 或 algo_new
    "metric_name": "assignment_latency_ms",   # 示例
    "metric_value": latency_ms,
    "payload": {"spot_id": spot_id, "status": status},
}).execute()
```

建议至少上报：`latency_ms`、`waiting` 次数、`shift_count`（若发生移位）；业务指标（预约完成率等）由车主端业务侧补录。

## 7. 一个月后：保留 / 退回

| 决策 | 操作（service_role 直改 experiments 表） |
|---|---|
| 保留 | `status = 'kept'`；把该算法设为车主端默认算法名，后续发布快照也以它为准 |
| 退回 | `traffic_pct = 0` 或 `status = 'rolled_back'`，秒级回旧 |
| 数据不够 | `traffic_pct` 加大或延长实验周期 |

## 8. 回滚保障约定

1. 新旧算法输出结构必须一致：都返回 `(Spot|None, "assigned"|"waiting"|"rejected")`；不兼容时在车主端写 adapter。
2. `experiment_assignments` 保证同一 user_id 在实验期内固定分组，不跳变。
3. `experiment_events` 全量留痕，回滚后可审计每个用户当时命中的算法版本。

## 9. 安全边界

- `algorithm_releases` / `experiments` / `experiment_assignments` / `experiment_events` 四张表全部 **RLS 开启、无 anon 策略**。
- 研发端网页通过 RPC（`publish_algorithm` / `list_algorithm_releases` / `list_experiments`，SQL 层校验仅管理员）读写；
- 车主端 FastAPI 用 **service_role key** 直连读写，**不得把 service_role key 下发到前端**。
