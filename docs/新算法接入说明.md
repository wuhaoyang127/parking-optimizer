# 新算法接入说明

本文档说明如何把一个新算法（单算法或融合算法）接入系统，接入后**网页会自动出现该算法的参数控件**，无需改动任何页面代码。

---

## 一、总体流程（3 步）

1. **写一个策略类**：继承 `BaseStrategy`（单算法）或 `CompositeStrategy`（融合算法）。
2. **声明可调参数**：用类属性 `PARAMS` 描述「有哪些参数、类型、范围、默认值」。
3. **登记**：在 `src/parking_opt/strategies/__init__.py` 里加一行 `StrategyRegistry.register(你的类)`。

完成后重启 Streamlit，策略下拉框就会出现新算法；选中后参数控件自动渲染；运行结果自动进入「参数调优历史」（每策略最近 5 次）。

---

## 二、策略基类约定

所有策略继承 `BaseStrategy`（`src/parking_opt/strategies/baselines.py`）：

```python
class BaseStrategy:
    name: str = "base"      # 英文唯一标识（登记键，不可重复）
    label: str = "基础策略"  # 网页显示名
    PARAMS: list = []       # 可调参数声明（见第三节）

    def assign(self, vehicle, time, parking_lot, path_engine):
        # 返回 (车位, 状态)，状态为 "assigned" / "waiting" / "rejected"
        raise NotImplementedError
```

**必须实现 `assign`**，它在每次有车辆到达、或等待队列重新调度时被调用。返回值约定：

| 状态 | 含义 | 返回 |
|---|---|---|
| `assigned` | 分配成功 | `(Spot 对象, "assigned")` |
| `waiting` | 当前无合适车位，进入排队等待 | `(None, "waiting")` |
| `rejected` | 明确拒绝 | `(None, "rejected")` |

> 大多数策略在车位满时返回 `waiting`（交给引擎排队，等待上限由环境参数控制），而不是直接 `rejected`。

---

## 三、参数声明 PARAMS

`PARAMS` 是一个列表，每项描述一个参数。`type` 支持 5 种：

| type | 网页控件 | 必需字段 | 说明 |
|---|---|---|---|
| `int` | 滑块 | `min` `max` `step` `default` | 整数参数 |
| `float` | 滑块 | `min` `max` `step` `default` | 小数参数 |
| `choice` | 下拉框 | `options` `default` | 枚举，`options=[(值, 显示名), ...]` |
| `bool` | 开关 | `default` | 布尔开关 |
| `strategy` | 下拉框（自动列已登记算法） | `default` | 融合算法选子算法用 |

通用可选字段：`label`（控件标题）、`help`（悬停说明）。`key` 必须是**构造函数的参数名**。

示例：

```python
PARAMS = [
    {"key": "threshold", "label": "时长阈值(秒)", "type": "float",
     "min": 600.0, "max": 7200.0, "step": 300.0, "default": 3600.0,
     "help": "停车时长低于该值优先分外层车位"},
    {"key": "warmup", "label": "自适应样本数", "type": "int",
     "min": 1, "max": 100, "step": 1, "default": 10,
     "help": "累计多少辆车后改用中位数自适应阈值"},
]
```

对应构造函数必须是：

```python
def __init__(self, threshold: float = 3600.0, warmup: int = 10):
    self.threshold = threshold
    self.warmup = warmup
```

> 约定：`PARAMS` 里每个 `key` 都要是 `__init__` 的关键字参数，且带默认值。这样网页用默认值初始化控件，并按用户调节后的值实例化算法。

## 四、单算法接入（完整示例）

以「最近空闲车位」为例：

```python
# 文件：src/parking_opt/strategies/my_algo.py
from .baselines import BaseStrategy


class MyNearest(BaseStrategy):
    name = "my_nearest"
    label = "我的最近算法"

    PARAMS = [
        {"key": "prefer_standalone", "label": "优先独立车位", "type": "bool",
         "default": True, "help": "开启后优先把车停到独立车位"},
    ]

    def __init__(self, prefer_standalone: bool = True):
        self.prefer_standalone = prefer_standalone

    def assign(self, vehicle, time, parking_lot, path_engine):
        available = parking_lot.get_available_spots()
        if not available:
            return (None, "waiting")
        # 若开启「优先独立车位」，只从独立车位里选
        if self.prefer_standalone:
            standalone = [s for s in available
                          if s.spot_type.name == "STANDALONE"]
            if standalone:
                available = standalone
        best = min(available, key=lambda s: path_engine.distance_to_spot(s.node_id))
        return (best, "assigned")
```

登记（`src/parking_opt/strategies/__init__.py`）：

```python
from .my_algo import MyNearest
StrategyRegistry.register(MyNearest)
```

重启后，策略下拉框出现「我的最近算法」，并带一个「优先独立车位」开关。

## 五、融合算法接入（完整示例）

融合算法继承 `CompositeStrategy`（`src/parking_opt/strategies/fusion.py`），它提供两个工具方法：

- `self._sub(name)`：按算法名实例化一个子算法（默认参数）；
- `self._sub_with(name, **params)`：按算法名 + 自定义参数实例化子算法。

融合的**具体逻辑**（时段切换 / 权重混合 / 概率选择）由你自己在 `assign` 里实现，融合比例用一个 `float` 参数暴露即可。系统已内置一个可参考的示例 `PeakOffPeakFusion`（高峰贪心 + 低谷最近，按占用率阈值切换）。

以「概率融合」为例（每次以 `ratio` 概率用主算法，否则用次算法）：

```python
# 文件：src/parking_opt/strategies/my_fusion.py
import random
from .fusion import CompositeStrategy


class RatioFusion(CompositeStrategy):
    name = "ratio_fusion"
    label = "概率融合（示例）"

    PARAMS = [
        {"key": "primary", "label": "主算法", "type": "strategy",
         "default": "duration_greedy", "help": "以 ratio 概率被选中"},
        {"key": "secondary", "label": "次算法", "type": "strategy",
         "default": "nearest", "help": "以 1-ratio 概率被选中"},
        {"key": "ratio", "label": "主算法概率", "type": "float",
         "min": 0.0, "max": 1.0, "step": 0.05, "default": 0.7,
         "help": "融合比例：选主算法的概率（可调）"},
    ]

    def __init__(self, primary="duration_greedy", secondary="nearest", ratio=0.7):
        self.primary = primary
        self.secondary = secondary
        self.ratio = ratio
        self._a = self._sub(primary)
        self._b = self._sub(secondary)

    def assign(self, vehicle, time, parking_lot, path_engine):
        if random.random() < self.ratio:
            return self._a.assign(vehicle, time, parking_lot, path_engine)
        return self._b.assign(vehicle, time, parking_lot, path_engine)
```

登记方式与单算法相同。网页上「主算法」「次算法」会自动列出所有已登记算法，「主算法概率」是 0~1 滑块。

> 要点：`type: "strategy"` 的参数，网页会**自动把已登记算法作为下拉选项**，同事不需要手工维护选项列表。

## 六、可用的领域/路网 API 速查

写 `assign` 时常用：

| 调用 | 说明 |
|---|---|
| `parking_lot.get_available_spots()` | 当前所有空闲车位（`list[Spot]`） |
| `parking_lot.get_outer_spots(spot)` | 挡住该车位离场的所有外侧车位 |
| `parking_lot.get_inner_spots(spot)` | 该车位内侧的纵深车位 |
| `parking_lot.get_group_spots(spot)` | 同一纵深组的全部车位（按 depth 排序） |
| `spot.spot_type` | `SpotType.STANDALONE`（独立）或 `SpotType.TANDEM`（纵深） |
| `spot.depth` | 纵深位置，`1`=最靠通道，`>1`=里层 |
| `spot.stack_group_id` | 纵深组 ID，同组车位共用 |
| `spot.node_id` | 路网节点 ID |
| `path_engine.distance_to_spot(node_id)` | 入口到该车位的最短路径距离 |
| `path_engine.shortest_distance(a, b)` | 两节点间最短距离 |
| `vehicle.estimated_duration` | 该车**预估**停车时长（在线算法可用） |
| `vehicle.parking_duration` | 真实停车时长（**在线算法不可读**，只供仿真/评估） |

> 信息边界提醒（项目硬约束）：时刻 `t` 的在线/动态算法只能访问「当前状态、已发生的到达离开、已知预约、用户提供的预估离场」。`vehicle.parking_duration` 是未来真值，在线算法不得读取，否则视为信息泄漏。

## 七、常见问题

1. **网页没出现我的算法**：检查是否在 `strategies/__init__.py` 登记，且 `name` 没有与现有算法重复；登记后需重启 Streamlit。
2. **参数控件没出现**：检查 `PARAMS` 里的 `key` 是否与 `__init__` 参数名完全一致，且都有默认值。
3. **运行时报「未知参数」**：`StrategyRegistry.create(name, **params)` 会把网页收集的参数原样传给构造函数，`PARAMS` 里多余的 `key` 若构造函数不接受会报 `TypeError`，请保持两边一致。
4. **融合算法选不到想要的子算法**：子算法必须先登记进 `StrategyRegistry`，`type: "strategy"` 的下拉选项来自注册表。
5. **有状态策略**：若算法内部会累积状态（如统计已见时长），注意引擎每次 `run` 会新建实例，多次运行（多 seed）也会各自新建，不会跨 run 污染。
