根据用户选择的 C 融合方向，制作一个可离线打开的 HTML/CSS/JavaScript 高保真交互原型：车主模式继承“城市智慧出行”的明亮、可信和地图优先结构；答辩模式吸收“未来停车舱”的深色科研驾驶舱、玻璃层次和动态语言。电脑与手机均保留完整核心功能。

## 范围

### 包含

- `prototypes/web-v2/` 下的零依赖静态交互原型；
- 车主模式：搜索、停车场比较、模拟实时空位、推荐、纵深说明、普通位备选、30 秒软锁和路线展示；
- 答辩模式：口令视觉占位、项目总览、算法状态、纵深移位交互、synthetic 证据和扩展说明；
- CSS 响应式布局，电脑和手机功能一致；
- 固定 synthetic 数据与确定性动画；
- 四类验收截图和原型说明。

### 不包含

- React、Vite、FastAPI、v2 Schema、真实 API 或依赖安装；
- 真正的鉴权、并发软锁、服务端倒计时或真实地图；
- 正式算法运行、实验结论或真实停车场数据；
- 自动驾驶轨迹、3D 引擎或第三方受保护素材；
- M2–M6 的实现。

## 冻结视觉决定

- 车主端：珍珠白与浅冰蓝表面、钴蓝主操作、青绿色可用状态、琥珀色风险提示；地图优先、结果先行。
- 答辩端：深海军蓝表面、青色与紫色强调、精密网格和玻璃卡片；证据与状态优先。
- 两种模式共享圆角、间距、字体尺度、状态色和品牌标识，不共享可变业务状态。
- 动效服务于状态理解：路线绘制、数字刷新、软锁倒计时、车辆移位和事件时间线；不使用持续炫光干扰阅读。

## 风险与降级

- 静态原型无法证明后端一致性：所有状态明确标记为 `synthetic prototype`，正式语义留到 M2/M3。
- 本机无浏览器自动化库：使用已安装 Chromium 浏览器的无头截图与 DOM 自检，不安装新依赖。
- 手机截图不能替代真实设备触控验收：M1 只验证响应式视口，真实 Safari/iPhone 仍是 M6 前置条件。
- 浏览器直接打开时部分安全能力不可模拟：答辩口令仅为视觉交互占位，正式鉴权必须由后端实现。
