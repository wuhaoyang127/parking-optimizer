## 3. 冻结数据与展示口径

| 场景 | 容量 | 充电位 | 纵深位 | 缓冲位 | 约占用率 |
|---|---:|---:|---:|---:|---:|

- 缓冲位不计容量且不可推荐；首批充电位与纵深位不重叠；
- 商场/枢纽以单向环流为主，学校/医院为双向主通道加局部单向停车排；
- 商场、医院、枢纽多入口或出口；学校单入口/单出口；
- 首批单层；公共资源支持楼层与显式跨层连接；
- 默认快照完整覆盖车位，可有少量明确 `unavailable`，不含人为 `unknown`；
- 空闲绿、占用深灰+车辆、推荐蓝、不可用红、未知黄、纵深紫色组框；
- 权威坐标为本地二维米制；像素/图像变换字段可空，只服务未来 M5 叠图。

## 4. 兼容契约方案（第一恢复点先冻结）

不得原地修改已批准 `Layout 2.0.0` 的必填字段。R0a 先提交公共变更提案并等待用户确认；R0b 再
实现两个独立的 additive 资源。不可变几何资源（工作名 `ParkingFacilityLayout 1.0.0`）最低包含：

- `parking_lot_id`、`layout_version` 和来源追踪；
- 本地坐标系、单位、边界、原点/轴方向；可选原图尺寸及米制↔像素变换；
- `floors`、当前首层、跨层连接；
- `zones`、不可通行区域和展示标签；
- 定向 `lanes/edges`、节点、宽度/方向/通行类型及路线引用；
- 入口/出口及服务端默认入口；
- 车位矩形几何、朝向、区域、类型、充电属性、接入节点；
- 纵深组、连续深度、专用缓冲位及缓冲接入节点；
- 可选展示层元数据只能影响样式，不得改变领域可行性。

动态 session-aware 状态快照（最终名称在 R0a 提案中确定）最低包含 `parking_lot_id`、
`layout_version`、`scenario_version`、`observed_at`、来源模式/健康和每个车位的权威状态。状态变化
不得改变布局身份；几何变化必须产生新 `layout_version`。

几何资源、状态快照和路线必须通过 `parking_lot_id + layout_version` 明确同源，动态状态另以
`scenario_version + observed_at` 标识。路线仍由既有
`Route` 返回，但所有 node/edge/space 引用必须能在完整布局中解析。车位状态来自同一 session-aware
权威快照，不在前端重新计算。

第一恢复点必须给出：新旧差异、为什么 additive、受影响端点、迁移、失败关闭、回滚、旧 Schema/
fixture 哈希证据和用户已批准决定。不得在字段语义未冻结时先写 React mock。
