# M1 第一审批门：视觉方向板执行计划

## 目标与用户可见结果

交付两套可直接比较的 Web v2 视觉方向板：

1. 城市智慧出行；
2. 未来停车舱。

每套方向板均包含车主模式和答辩模式的电脑、手机关键片段，并保存为项目内 PNG。完成后停止，
等待用户选择、融合或要求修改，不进入 M1 第二审批门的 HTML/CSS 高保真原型。

- 文档基线提交：`d1c0d27`；
- 当前分支：`codex/web-v2-m1-prototype`；

- M1 第一审批门已获授权；第二审批门未获授权。

## 范围

### 包含

- 两套横向高保真视觉方向板；
- 每套同时展示电脑车主端、手机车主端、电脑答辩端和手机答辩端；
- 体现停车场搜索、模拟实时空位、推荐、30 秒软锁、路线、纵深位、缓冲位、算法状态和导航；
- 使用位图生成工具制作初稿，并进行中文、层级、状态颜色和移动端密度检查；
- 在 `docs/design/web-v2/` 保存 PNG、方向说明和审批记录占位。

### 不包含

- HTML/CSS/JavaScript 可交互高保真原型；
- React、FastAPI、v2 Schema、依赖安装或算法实现；
- 品牌命名、真实地图、真实数据或实车导航；
- 对视觉方向做最终选择。

## 关键定义与假设

- 两套方向都遵守车主模式明亮、答辩模式深色的双主题边界；
- “城市智慧出行”强调明亮、克制、可信赖、地图产品感；
- “未来停车舱”强调更强科技感、玻璃层次和答辩视觉冲击，但车主端仍需清晰可用；
- 所有数字和状态明确属于模拟演示；
- 方向板中的文字是视觉文案，不冻结 API、算法、并发或安全语义；
- 位图中的细小中文可能出现生成误差，方向板以整体风格、布局和状态语义审批为主；关键文案在
  后续代码原型中使用真实 HTML 文本实现。

## 详细实施步骤

1. 为两套方向建立独立、结构对齐的图像生成提示词，保证比较维度一致。
2. 分别生成一张 16:9 横向视觉方向板，避免将其误作可运行网页截图。
3. 检查以下结构是否都存在：
   - 品牌栏和模式入口；
   - 停车场卡片、模拟位置图和实时空位；
   - 推荐结果、纵深风险、合规备选和 30 秒软锁；
   - 场内路线和车辆；
   - 答辩导航、算法选择器、待接入状态、纵深与缓冲位；
   - 电脑和手机片段。
4. 将最终 PNG 保存到 `docs/design/web-v2/direction-boards/`。
5. 在 `docs/design/web-v2/m1-visual-review.md` 记录两套方向的色彩、排版、组件、动效倾向、优势、
   风险和建议选择方式。
6. 更新本计划和 `WEB_V2_STATUS.md`，将状态置为等待视觉选择。

## 验证与验收

- 文件存在且能被图像查看工具读取；
- 图片为横向方向板，分辨率足以在电脑上比较；
- 两套均包含电脑和手机、车主和答辩四类片段；
- 车主端不展示算法研究信息；答辩端显示在线规则与待接入算法；
- 双主题、synthetic 标签和纵深停车特色可见；
- 不出现真实品牌、真实地图、照片水印或自动驾驶能力暗示；
- `git diff --check` 通过；
- 未创建正式产品实现目录。

## 风险与降级

- 图像生成对小字号中文可能不稳定：保留整体方向板用于风格审批，在评审说明中给出准确文案；
- 一张图信息密度过高：优先保证四类关键片段和视觉系统，细节不作为交互规格冻结；
- 某套风格影响可读性：只迭代该方向的层级、对比度或密度，不改变另一套对照；
- 图像工具不可用：停止并报告，不用低质量占位图冒充方向板。
