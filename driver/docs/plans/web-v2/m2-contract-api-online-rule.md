# M2：v2 契约、API 与在线规则服务

## 目标与用户可见结果

建立 Web v2 的第一套正式后端契约和可调用 API。完成后可以在没有前端的情况下：列出四个版本化 synthetic 停车场、读取布局和算法状态、提交一个停车推荐请求，并得到经过充电硬条件、可达性、动态成本、纵深恢复和结果复核的确定性推荐或结构化失败。

M2 结束时冻结 v2 资源与 API 语义，停止等待用户验收；不自动进入会话状态机、多车动态仿真或 React 页面。

## 当前状态

- M1 已由用户验收，标签为 `web-v2-m1-approved`；
- 当前分支：`codex/web-v2-m2-contract-api`；
- v1 契约、在线规则、实验与证据保持只读；
- 当前核心依赖只有 JSON Schema 工具；FastAPI、Uvicorn 和 HTTPX 尚未作为 M2 直接依赖锁定；
- 四个 Web v2 synthetic 停车场和 `schemas/v2/` 尚未创建。

## 范围

### 包含

- `schemas/v2/` 中版本化 JSON Schema、字段说明与版本策略；
- 商场、学校、医院、交通枢纽四个只读 synthetic 初始场景；
- 纯 `RouteCostService`，读取版本化布局与给定成本快照，返回确定性路线和成本；
- v1 只读适配器和导入边界；
- `OnlineRuleServiceV2`：充电硬过滤、v1 可行性/纵深恢复复用、动态路径排序、确定性解释与结果复核；
- FastAPI 应用骨架、健康检查、错误模型、OpenAPI、数据源接口、算法注册表和 `SessionStore` 协议；
- 普通位、纵深位、充电、无位、不可达、成本改变排序、结构化失败与显式降级测试；
- v1 文件哈希基线和未修改检查。

### 不包含

- 软锁、五分钟预留、幂等状态机和匿名会话具体实现；
- 动态事件生成、偏航、外部占位冲突和多车仿真；
- React/Vite 前端或 M1 原型改造；
- 真实停车场连接、账户、支付、生产权限或公网部署；
- 模拟退火、随机森林或其他待接入算法的实现；
- 对 v1 Schema、策略、测试、实验结果或证据文件的修改。

## 关键定义与假设

- Schema 版本从 `2.0.0` 开始，API 前缀为 `/api/v2`。
- 所有时间使用带时区 RFC 3339 字符串，或字段名明确为 `_s` 的仿真秒/持续秒；距离统一为米。
- `parking_lot_id` 是所有布局、车位、路线和请求的作用域；跨停车场 ID 不得混用。
- 真实数据源缺少必填字段时失败关闭；切换 synthetic 必须由调用者显式请求，不能混合补值。
- M2 推荐只生成候选结果，不创建软锁或预留；资源声明与权威时钟属于 M3。
- 充电是硬条件。需要充电时，非充电位在调用 v1 结果前后都不会被选中；适配器仍以完整布局和完整占用快照评估 v1 可行性，避免改变容量与纵深语义。
- 动态成本是调用者提供、带版本的当前可见快照，不由 M2 预测或生成；未知边、负成本或版本不匹配失败关闭。
- 排序使用词典序，不做跨单位加权和：硬条件/可恢复性 → 动态 ETA → 路程 → 纵深深度 → 稳定 ID。
- 在线信息只包含当前观测、已知预约和请求字段；不得读取未来事件或 oracle。
- v1 适配结果必须经过 v2 复核；失败或超时时显式记录状态与降级原因，不冒充主算法成功。

## 详细实施步骤

1. 在 `schemas/v2/` 建立自包含 JSON Schema 目录，并在 `src/parking_opt/api/contracts.py` 提供加载与校验入口。
2. 在 `data/synthetic/web-v2/` 保存人工设计、版本化、可审查的小型场景；场景文件直接满足 v2 Schema，不从输出目录反向生成。
3. 在 `src/parking_opt/api/routing.py` 实现无全局状态的路由成本计算；同成本时按节点/边 ID 决定性破平。
4. 在 `src/parking_opt/api/adapters/v1.py` 形成唯一 v1 适配边界，禁止 API 其他模块直接依赖 v1 策略内部实现。
5. 在 `src/parking_opt/api/services/online_rule.py` 组合候选、硬过滤、路由成本和解释；将主算法、复核和降级状态分开记录。
6. 在 `src/parking_opt/api/app.py` 建立应用工厂，在 `routes/` 中保持薄端点；错误统一映射到版本化错误模型。
7. 在 `tests/web_v2/` 按 contracts、routing、services、api 和 boundaries 分组测试，并保留极小手算场景。

## 验证与验收

- 所有 v2 示例都通过 JSON Schema 与语义校验，非法跨作用域、负成本、未知边、深度断层和缺失必填字段失败；
- OpenAPI 与代码模型一致，错误响应包含稳定 code、message、details 和 request_id；
- 推荐结果明确包含算法 ID/版本、状态、主位、合规备选、路线、解释、数据源和成本版本；
- 充电请求绝不返回非充电位；普通位备选也满足相同硬条件；
- 动态成本快照变化能在固定极小例中改变排序；
- 无合规车位、不可达、适配失败和超时都显式返回失败或降级记录；
- v1 受保护文件 SHA-256 与 M2 起始基线一致；
- 测试、Ruff、Mypy 和 Diff 检查实际通过。

## 风险与降级

- FastAPI 新版依赖变动：锁定已核验版本，先运行最小导入和 TestClient；不使用 `fastapi[standard]` 扩展集。
- v1 输入模型过重：先建立最小、显式、可审计的 v1 投影；若语义无法安全复用，保留 v1 作为对照并实现不冒名的 v2 确定性策略，同时记录偏离并请求用户确认。
- synthetic 场景过大：M2 只建立能覆盖契约与算法边界的小型完整场景；商业展示密度留到 M4。
- NetworkX 不可用：`RouteCostService` 可使用第三方无关的确定性 Dijkstra 实现；不为 M2 强制启用 graph extra。
- 性能阈值尚未冻结：M2 只记录测量值和正确性，正式预算在对应后续计划中冻结，不根据结果反向放宽。
