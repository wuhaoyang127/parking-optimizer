# M3：共享状态机、动态路线与确定性多车仿真

## 目标与用户可见结果

在没有 React 前端的情况下，通过 FastAPI 和测试客户端完整运行一次匿名 synthetic 停车流程：
推荐并原子软锁车位、确认预留、开始导航、动态重规划、确认占用、离场或重置；同时提供隔离的
答辩仿真命名空间、确定性多车事件流、纵深移位和失败案例。所有业务倒计时由服务端权威墙钟
控制，固定种子仿真可重放并得到相同事件与最终状态哈希。

M3 完成后停止等待用户验收，不创建 React 页面、不进入答辩可视化 M5，也不修改 v1 受保护资产。

## 当前状态

- M1、M2 已获用户验收，M2 标签为 `web-v2-m2-approved`；
- 当前分支为 `codex/web-v2-m3-state-simulation`；
- M2 已提供 v2 契约、四个 synthetic 场景、`RouteCostService`、只读 v1 适配、
  `OnlineRuleServiceV2`、数据源边界和 FastAPI；
- `SessionStore` 目前只有协议，`Journey` 和 `SimulationEvent` 是 M2 占位契约；
- 历史 D2/D3 CRLF 哈希问题不属于 M3，不修改旧证据来掩盖它。

## 范围

### 包含

- driver/defense 双命名空间、匿名会话、场景克隆、闲置 TTL 和垃圾回收；
- `IDLE / WAITING / SOFT_HELD / SESSION_RESERVED / NAVIGATING / OCCUPIED /
  DEPARTED / CANCELLED / EXPIRED / FAILED` 状态机；
- 30 秒软锁、车主 5 分钟预留、答辩 60 秒映射、幂等命令和版本冲突；
- 单进程内存 `SessionStore`、原子车位声明和可替换存储接口；
- M2 推荐与有效声明/占用投影、ETA + 60 秒安全检查、备选原子切换；
- 通道占用驱动的版本化成本快照、偏航、外部占位冲突和路线重规划；
- 固定种子的二维管理层多车事件引擎、纵深移位、缓冲不足、等待与重放哈希；
- v2 Schema、OpenAPI、FastAPI 无 UI 演示端点、审计事件和失败关闭；
- 正确性、隔离、复现、性能、v1 哈希和全仓回归验证。

### 不包含

- React/Vite 页面和前端状态管理；
- 答辩口令、研究证据 UI、自由实验台、伪 3D 或声音；
- Redis、数据库、多 worker、一致性集群或生产并发承诺；
- 真实停车场锁位、账户、支付、真实感知或车辆控制；
- 新推荐算法、预测模型或对 v1 文件/实验产物的修改。

## 关键定义与冻结参数

- 车主命名空间 `driver` 和答辩命名空间 `defense` 的可变场景完全隔离，只共享只读布局版本；
- 车主闲置 TTL 为 1,800 秒，答辩闲置 TTL 为 7,200 秒；
- `SOFT_HELD` 为 30 秒；车主 `SESSION_RESERVED` 为 300 秒，答辩映射为 60 秒；
- 业务墙钟使用 UTC 到期时间供显示、单调时钟计算持续时间；刷新、断线、模式切换和导航不续期；
- 主推荐须满足 `route.dynamic_eta_s + 60 <= 300`，重规划超过剩余期限时明确警告或重新推荐；
- 一个 driver 会话最多有一个活动等待、声明、预留或行程；备选不预锁；
- 命令幂等键在同一会话和操作作用域内唯一；相同键和相同输入返回原结果，不同输入冲突；
- 所有状态变更生成带前后状态哈希的顺序事件；不得读取未来事件或仿真真值来做在线推荐；
- 性能预算：命令 p95 ≤ 100 ms，推荐+软锁 p95 ≤ 500 ms，重规划 p95 ≤ 100 ms；
  100 辆车、10,000 事件重放 ≤ 2 秒且增量峰值内存 ≤ 256 MB；
- 上述性能是单进程、本地答辩电脑、synthetic 数据条件下的原型验收，不是生产 SLA。

## 详细实施步骤

1. 在 `configs/web-v2/` 保存 M3 时间和性能配置，由服务与测试共同读取，避免散落魔法数字。
2. 在 `src/parking_opt/api/models.py` 冻结会话、声明、命令、事件和动态成本所需契约并重新导出
   `schemas/v2/`；公共语义变化同时更新 OpenAPI。
3. 在 `src/parking_opt/api/sessions.py` 和独立状态机模块中实现存储接口、原子操作、版本控制、
   幂等结果与 GC；不把业务真值放在 FastAPI 路由函数中。
4. 将有效声明和占用投影为 M2 推荐的当前可见输入；推荐成功后在同一临界区声明主位，冲突时
   重新评估或返回结构化冲突，绝不先响应再锁位。
5. 在动态成本模块中从当前通道占用派生完整 `CostSnapshot`，通过 M2 `RouteCostService` 重规划。
6. 在仿真模块中使用显式优先级队列、固定种子和稳定 ID 生成事件；每次转换保存前后规范哈希。
7. 在 `tests/web_v2/` 按 state、sessions、routing、simulation、api、performance 分组测试，并保留
   可手算的单车、双车、纵深两层和单缓冲极小场景。

## 验证与验收

- 状态转换表每条合法边和每个非法入口都有测试；资源声明与车位状态始终一一对应；
- 30 秒、300 秒、60 秒、1,800 秒和 7,200 秒边界使用可控时钟精确验证；
- 相同幂等键不重复产生声明或事件，不同载荷返回结构化冲突；
- driver/defense、不同匿名会话和不同停车场之间无可变状态泄漏；
- ETA 安全余量、备选切换、偏航、外部占位、缓冲不足、过期和 GC 均失败关闭并可审计；
- 固定种子事件序列、前后哈希和最终状态哈希一致，无未来信息泄漏；
- 实际测量并满足冻结性能预算，不在看到结果后放宽阈值；
- OpenAPI/Schema、测试、Ruff、Mypy、v1 哈希和全仓回归实际通过或历史失败被准确隔离记录。

## 风险与降级

- 单进程内存状态不适合多 worker：M3 明确拒绝多 worker 生产承诺，存储协议保留共享事务实现；
- 墙钟跳变：期限计算只使用单调时钟，UTC 仅用于展示和审计；
- 推荐与声明竞争：在存储临界区复核并声明，冲突返回稳定错误，不静默选择未经解释的车位；
- 10,000 事件预算过紧：先优化数据结构和哈希边界，不删除审计事件、不改测试规模或放宽阈值；
- Streamlit 历史夹具哈希失败：只在隔离副本规范化换行验证全仓，不修改旧证据掩盖问题。
