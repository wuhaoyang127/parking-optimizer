# AGENTS.md

## 1. 适用范围与目标

本仓库当前主开发目标是“智能停车优化与调度系统 Web v2”：React + TypeScript + Vite 前端、
FastAPI 应用层和版本化 v2 契约。目标是形成面向普通车主、可用于大创答辩、电脑和手机功能完整，
并可逐步接入真实停车场数据的高质量商业化演示原型。

本文件是 Web v2 的唯一开发治理规则。旧 Streamlit、旧 A–D 阶段、`PROJECT_STATUS.md` 和 v1
实验产物均属历史资产；除非用户明确要求，不参与 Web v2 的授权、阻断或完成判断，也不得被改写。

当前成果不是生产系统，不得宣称具有真实车辆感知、自动驾驶控制、避碰或可下发车辆的轨迹能力。

会改变范围、主要交互、数据语义、算法输入输出、公共接口、关键依赖或交付方式的歧义必须先问；

## 4. 当前阶段边界

- 当前 M4 正在完成“完整停车场布局基础层”：兼容资源、四套大布局、共享二维画布、车主布局
  预览、当前行程完整布局和全端验收；精确恢复点与授权只读 `WEB_V2_STATUS.md`。M4 再次验收前

- M5 才实现答辩总览、口令会话、布局/状态/需求导入、场景编辑、批量评估、算法对比和报告。

- 跨模块、公共契约或超过一小时的任务必须建立 ExecPlan；每个恢复点先测试、审查，再单独提交。

## 5. 产品和真实性硬要求

- 默认车主模式只展示完成停车所需信息，隐藏算法名、参数、权重和技术下载。
- 答辩模式从首页入口进入，但必须由后端环境口令保护；路由与状态不能只靠隐藏按钮隔离。
- 车主与答辩仅共享停车场 ID 和已发布只读布局；软锁、预留、占用和实验修改按会话/命名空间隔离。
- 四类停车场为商场、学校、医院、交通枢纽，synthetic/导入/真实来源必须显式标记。
- 未知状态不是空闲；真实数据缺失或适配失败必须失败关闭，不得用 synthetic 字段补真实场景。
- 页面只显示管理层二维布局与路线；车辆移动是 Route 的 UI 插值，不能冒充实时定位，动画结束
  不能自动提交停车。
- 纵深位必须明确 `stack_group_id`、`depth`、专用缓冲位、可达路线和失败条件；缓冲位不可推荐。
- 电脑和手机核心能力一致；响应式只调整布局、密度和操作承载。

## 6. 布局、数据和算法边界

- 保留获批的 `Layout 2.0.0` 与 legacy 小场景；完整设施布局使用新增、版本化、兼容资源，不在前端
  写死道路、车位或 ID 映射。公共字段变化先记录差异、迁移、测试和回滚，再实施。
- 权威几何使用本地二维米制坐标；原图像素坐标只用于答辩叠图校验，不参与距离计算。
- 布局、状态快照和需求事件是独立输入；`unknown` 一律排除推荐。在线算法不得读取未来事件真值。
- 预测值、用户输入、当前观测和仿真真值分字段保存并标注来源；在线与对比算法只能消费当时
  可见的观测和合法输入，不得读取 oracle 或未来真值。
- React 不实现推荐、锁位、寻路、指标或状态机；FastAPI/Python 是业务结果权威。
- 车主模式唯一算法仍为验证通过的 `OnlineRuleServiceV2`，界面称“智能推荐”。
- M5 可在答辩命名空间注册验证通过的 `nearest_feasible_v1` 和 `random_feasible_v1` 作为实验基线；
  未通过统一契约、硬约束、公平性和复现测试前必须保持 `pending`，不得产生伪结果。
- 算法注册表区分 `available`、`pending`、`failed` 和降级；预测模块与分配算法分开。
- 算法比较必须同布局、同状态、同需求、同可见信息和同预算；随机方法记录种子并保留失败。

## 7. 工程、安全和 Git

### 7.1 单文件行数上限（强制）

- 本仓库所有 Python 文件（源码 / 测试 / 脚本）单文件不得超过 **200 行**；
- 超过 200 行必须按功能拆分：一个功能一个文件，禁止为凑行数而胡乱拆分；
- 新增文件同样受 200 行限制。

- TypeScript 严格类型；前后端运行时输入均失败关闭；错误、加载、空数据、离线和降级可见。
- 默认不新增关键依赖；确需新增时先说明用途、许可证、Windows/Python 3.11/浏览器兼容、包体和
  部署影响，并锁定版本和增加最小测试。
- 口令、密钥和真实个人信息不入库；口令来自环境变量，服务端签发短期会话。公网要求 HTTPS、
  安全头、同源校验、速率限制和日志脱敏。
- 不修改用户已有未提交文件，不做无关重构或全仓格式化。删除、迁移、公共接口变化前创建恢复点。
- 不提交 `.env`、`node_modules`、构建缓存、本机绝对路径或未脱敏数据。
- 禁止使用 `git add .`、`git add -A` 或按目录盲目暂存。提交前用明确文件白名单暂存，并核对
  `git status --short`、`git diff --check`、`git diff --cached --check` 和 staged 文件清单；用户未跟踪
  资产保持未跟踪，除非用户明确逐项授权纳入。
- 只在用户要求或计划明确包含时提交 Git；提交保持单一恢复点，标题使用 `feat(web): 中文说明` 等，
  正文按需记录 Why / What / Validation / Boundary。推送、合并、打 tag 必须有用户明确授权，提交
  成功不等于已经推送。

## 8. 验证和完成定义

行为变化必须有相称验证，按漏斗执行：定向单元/Schema → 类型/lint → 后端回归 → 前端组件 →
双视口 E2E → 真实 FastAPI 联调 → 视觉/性能。只报告实际运行结果，失败和降级必须保留。

浏览器验收必须使用当前构建与真实 FastAPI；mock 只能作为快速状态门，不能替代真实联调。视觉
证据必须实际检查桌面和手机的文本截断、遮挡、横向溢出、触控目标、全屏/滚动、错误/空状态和
reduced motion。运行中的旧服务不能当作当前代码证据；先确认进程对应本工作区和当前构建。

至少覆盖：字段与引用校验、布局连通/方向、状态与声明一致性、30 秒软锁、纵深/缓冲失败、路线
同源、固定种子、未来信息泄漏、模式/会话隔离、断线恢复、电脑/手机和回滚。性能阈值在测量前
冻结，不得看到结果后放宽。

任务完成时必须列出修改、实际验证、未完成项和风险；同步需求/决策/计划/状态，检查 Diff，不覆盖
历史资产。里程碑只有在实现、契约、测试、文档一致且用户验收后才可标记 `approved`。

## 9. 本地运行与交接

- Web v2 开发验收入口为 `npm --prefix apps/web run demo`：先构建生产资源，再在回环地址启动
  FastAPI `127.0.0.1:8000` 和 Vite preview `127.0.0.1:4173`；健康检查分别为
  `/api/v2/health` 和网站首页。端口被未知服务占用时停止并报告，不得直接终止未知进程。
- `apps/web` 要求 `package.json` 中锁定的 Node/npm 主版本；Python 使用仓库 `.venv` 和项目冻结的
  Python 3.11。缺依赖时先报告影响和可复现安装方式，不得静默改用全局环境。
- 结束本地服务使用启动终端的 `Ctrl+C`，并确认两个端口均已释放；不得遗留后台进程冒充可交付
  一键启动。
- 阶段交接必须写明分支、提交、状态字段、已运行验证、证据路径、已知限制、未跟踪资产和唯一
  下一步。接收方仍须自行核验 Git 和权威文件，不得仅相信交接摘要。
